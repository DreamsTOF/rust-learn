# Tauri v2 练习项目 — 直观版计划（v2）

## 定位

面向已有 Rust 基础、想学 Tauri v2 桌面开发的读者。**每课一道菜**：从一个真实需求出发，交付一个完整可运行的小应用。知识在用到的时候讲，**只讲本课新增的部分，并且讲透**——不满足于"能跑"，而是让读者知道每一行为什么这样写。

## 一、设计原则

| 原则         | 做法                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------- |
| 每课一道菜   | 每课一个完整、可见、能玩的小应用，不做抽象 API 切片练习                                     |
| 需求引出知识 | 每个知识点由真实痛点引出："关掉软件字就没了 → 学文件保存"；"几百个文件要改名 → 学进度条"  |
| 只讲新增     | 循序渐进：每课只讲解本课新增的知识，旧知识一句话带过并指出出处（"沿用 a0X"）                |
| 讲解讲透     | 每个新 API 讲四件事：解决什么问题 → 怎么用 → 有哪几种写法 → 为什么选这种                 |
| 练习 + 答案  | 每课两个项目：练习版（TODO 填空）+ 答案版（完整代码）；讲解成书（mdbook），参考答案折叠可查 |
| 挑战收尾     | 每课 1-2 个升级挑战，改几行加个小功能，确认真的会了                                         |

**学习建议（写给会觉得"为什么是这样"的人）：** 脚手架生成的东西 90% 现在不需要懂。看不懂的配置先跳过，等真的需要改它时再回来讲解。永远先让代码跑起来，再问为什么。

## 四、每课两个文档：练习讲解 + 答案讲解

每课 = 两个 mdbook 文档（练习讲解 + 答案讲解）+ 两个项目（练习版 + 答案版）。

**两文档怎么配合：** 先读练习讲解——讲透原理并指路作业；卡住时再打开答案讲解，逐 TODO 对照。两文档用"回查文档"锚点互相链接，单向依赖、内容不重复。

> **范本：** 讲解格式与质量以原书 [01_hello_world.md](file:///c:/code/testruetlearn/tauri-learn-book/src/01_getting_started/01_hello_world.md)（练习讲解）和 [01_hello_world_answer.md](file:///c:/code/testruetlearn/tauri-learn-book/src/01_getting_started/01_hello_world_answer.md)（答案讲解）为范本，本次计划将其固化为标准格式。

### 练习讲解（`NN_topic.md`）—— 先讲透，再做菜

固定 5 段：

1. **为什么要学这个** —— 本课回答的 2-3 个问题（如"一个项目为什么有两个 `src`？"）
2. **从问题出发** —— 一句话需求 + 核心矛盾（前端做不到 → 所以架构分工）+ 架构图；不直接甩代码
3. **新增知识详解** —— 只讲本课新增，按小节展开；每个新 API 讲四件事（解决什么问题 → 怎么用 → 有哪几种写法 → 为什么选这种），配"关键理解"提示、对比表、序列化/调用流程图；旧知识只标注"沿用 a0X"，不重复展开
4. **练习指引** —— 作业范围（动哪几个文件）、每处 TODO 的提示、怎么运行验证
5. **知识点连起来看** —— 分层总结表 + "一通百通的核心" + 递进关系（下一课讲什么）

### 答案讲解（`NN_topic_answer.md`）—— 卡住时再看

固定 5 段：

1. **用法 + 作业范围** —— 开头注明"卡住时再看本页"；本课只需动哪几个文件
2. **对照总览** —— 表格：文件 / 练习版状态 / 你缺的
3. **逐 TODO diff** —— 每处 TODO 四步：练习版这里是什么 → 答案版填了什么 → 为什么（讲透）→ 回查文档（锚点链回练习讲解对应小节）
4. **验收标准** —— 运行命令 + 预期现象
5. **破坏性验证** —— 故意改错 1-2 处（改命令名、删注册、改返回值），写清"改前现象 → 改后现象"，确认理解而不是碰巧

### 讲解标准（详细详细再详细）

| 要求           | 说明                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| 从问题出发     | 每课从"核心矛盾"切入（如"前端是沙箱，检查环境必须靠后端进程"），不直接甩代码    |
| 一图胜千言     | 双进程、调用链、序列化过程（Rust → JSON → TS）都配 ASCII 流程图               |
| 对比表讲清选择 | "命令 vs 普通函数""fetch vs invoke"式的表格，讲清为什么这样设计                 |
| 逐行拆解       | 新 API 涉及的关键行逐行讲，不满足于"能跑"；配合"去掉它会怎样"                   |
| 双向回查       | 答案讲解每处 TODO 有"回查文档"锚点链接；练习讲解给官方文档深挖链接              |
| 破坏性验证     | 每课验收配"改一行看什么变化"，用动手代替死记                                    |
| 前端速成前置   | 前端语法不熟时配"给 Vue 开发者"式速成文档（Vanilla TS / React），不占用正课篇幅 |
| 只讲新增       | 每课只讲解本课新增知识，旧知识标注出处，不重复展开                              |

### 练习版 / 答案版约定

- **练习版**：目录名不加后缀，含中文 TODO 注释，只留骨架；答案版目录名加 `_answer` 后缀。
- **答案版**：完整代码，`lib.rs` / `main.ts` 与练习版一一对应，零 TODO。
- 两版共用同一份 `tauri.conf.json`（devUrl 端口 = 1420 + 题号，答案版端口 +1，标题加"（答案）"）。
- 每个练习/答案项目必须通过 `cargo tauri build --no-bundle`。

### TODO 密度（引导随难度递减）

| 课         | TODO 密度     | 代码完成度  |

| e01 计数器 | 逐行 TODO     | 只需填空    |
| a01-a02    | 每步详细 TODO | 补全约 30%  |
| a03-a05    | 关键位置 TODO | 补全约 50%  |
| a06-a08    | 仅功能目标    | 骨架 + 自写 |

## 阶段 1：环境与第一个窗口（1 课）

**目标：装好工具链，跑起第一个应用，看懂目录。**

章节内容：

1. 前置条件检查（一条命令确认 Node / pnpm / Rust stable）
2. `create-tauri-app` 创建项目
3. 看懂目录：
   - `src/`：房子的装修（前端，你看到的东西）
   - `src-tauri/`：承重墙（后端，窗口、文件、系统能力）
4. `pnpm tauri dev` 跑起来
5. 第一道菜：计数器（约 60 行）

**新增知识（本课讲透）：** `invoke`（前端给后端打电话）、`#[tauri::command]` + `generate_handler!`（登记电话号码簿）、`serde`（两边讲同一种语言）。

**练习版：** 给出窗口和按钮骨架，TODO 填 `count` 命令与 `invoke` 调用。

**升级挑战：** 加一个"清零"按钮；或改成两个按钮（+1 / -1）。

## 阶段 3：超级项目（26 步）

**Markdown 编辑器** —— 串行递进，每步依赖前一步，最终交付可安装分发的完整产品。

- 阶段 A 骨架（P1-P3）→ 阶段 B 核心编辑（P4-P8）→ 阶段 C 体验完善（P9-P14）→ 阶段 D 桌面能力（P15-P18）→ 阶段 E 高级功能（P19-P22）→ 阶段 F 发布（P23-P26）
- 每步一个功能目标，代码几乎全写（与练习版不同，不设 TODO 填空）
- mdbook 每阶段两文档（练习讲解 + 答案讲解），集中讲解该阶段出现的新 API、架构决策与"为什么这样设计"
- 前置依赖：八道小菜已覆盖全部前置 API
