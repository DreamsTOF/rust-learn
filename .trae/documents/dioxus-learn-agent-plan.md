# Dioxus 练习项目 — Agent 编写规划

## 1. 概述

约 **535 项练习内容**（415 道独立题 + 120 步项目）全部由 AI Agent 自动编写。本文档定义 agent 的编写流水线、并发策略、验证门禁和质量标准。

### 核心原则

| 原则                 | 说明                                              |
| -------------------- | ------------------------------------------------- |
| **模板驱动**   | 每道题从模板 crate 生成，避免重复脚手架           |
| **并行最大化** | 无依赖的章节并发编写，有依赖的章节串行编排        |
| **验证前置**   | 每道题写完即`dx build`，不过关不留到下个阶段    |
| **幂等生成**   | 同一个 agent 重复运行同一道题应产生相同代码       |
| **答案分离**   | 每题生成两个 crate：练习 + `*_answer` 参考答案    |

## 3. 练习 crate 模板

### 3.1 标准 Web 模板（第 0-7 章、第 9-10 章）

每道题生成两个独立 crate：

```
01_basics/
├── eNNN_exercise_name/                 ← 练习 crate（含 TODO）
│   ├── Cargo.toml
│   └── src/
│       └── main.rs
└── eNNN_exercise_name_answer/          ← 答案 crate（完整可编译）
    ├── Cargo.toml
    └── src/
        └── main.rs
```

**练习 main.rs 模板：**

```rust
// ============================================================
// 练习 N: 题目名称
//
// 目标: 一句话描述本练习要掌握的知识点
//
// TODO: 按照注释提示补全代码
// ============================================================

use dioxus::prelude::*;

fn Exercise() -> Element {
    // === 步骤 1 ——————————————————————————————————————————
    // TODO: 创建一个计数信号，初始值为 0
    // 提示: 使用 use_signal(|| ...)

    // === 步骤 2 ——————————————————————————————————————————
    // TODO: 在视图中显示当前计数值

    rsx! {
        div {
            // 你的代码在这里
        }
    }
}

fn main() {
    dioxus::launch(Exercise);
}
```

**答案 main.rs 模板：**

```rust
// ============================================================
// 练习 N: 题目名称 — 参考答案
// ============================================================

use dioxus::prelude::*;

fn Exercise() -> Element {
    let mut count = use_signal(|| 0);

    rsx! {
        div {
            p { "Count: {count}" }
            button { onclick: move |_| count += 1, "Increment" }
        }
    }
}

fn main() {
    dioxus::launch(Exercise);
}
```

### 3.3 难度引导模板

根据难度等级，TODO 引导程度不同（练习与参考答案各一份）：

| 难度              | TODO 密度         | 练习代码完成度 | 参考答案完整度 |
| ----------------- | ----------------- | -------------- | -------------- |
| ⭐ (eN+0, eN+1)   | 每行都有详细 TODO | 只需填空       | 完整可编译     |
| ⭐⭐ (eN+2, eN+3) | 关键位置有 TODO   | 补全约 50%     | 完整可编译     |
| ⭐⭐⭐ (eN+4)     | 仅描述目标        | 仅骨架         | 完整可编译     |

## 4. 并发策略

### 4.1 核心模型：章内 Batch 并发

每个练习 crate 之间**完全独立**（无共享代码、无编译时依赖），因此并发粒度可以下探到 **batch 级别**——同一章内的多个 batch 同时由不同 agent 编写。

```
章节 (N 题)
├── Batch 1 (eX ~ eY)  ← Agent A
├── Batch 2 (eY+1 ~ eZ) ← Agent B    ← 同时启动
├── Batch 3 ...         ← Agent C
└── ...
```

**为什么这可行：**

- 每个练习是一个独立的 Cargo crate，不共享 `src/` 下的代码
- workspace Cargo.toml 的 `members` 列表在 Phase 0 预注册所有路径，不存在写冲突
- 唯一共享的文件是 `workspace Cargo.toml`，但 `members` 可以一次性声明所有路径
- Dioxus 项目使用 `dx build`，不依赖 Trunk，避免端口冲突问题

### 4.2 Batch 划分规则

```
每章题数 ÷ 5 = agent 数（向上取整）

固定规则:
- 每个 agent 固定负责 **5 道题**（即 10 个文件夹：5 练习 + 5 答案）
- 一个 batch 内的题尽量来自同一子节（知识点连贯）
- 章节题数不能被 5 整除时，余数题由最后一个 agent 额外承担
```

### 4.3 各章节 Batch 分配矩阵

每个 agent 固定负责 **5 道题**（10 个文件夹）。每 batch 内的题号按连续 5 题划分。

#### Phase 1: 第 0-3 章（全部同时启动）

| 章节 | 题量 | Agent 数 | Batch 划分（每 batch 5 题） |
| :--: | :--: | :------: | :------------------------- |
| Ch0  |  10  |    2    | e001-e005 / e006-e010 |
| Ch1  |  20  |    4    | e011-e015 / e016-e020 / e021-e025 / e026-e030 |
| Ch2  |  75  |   15    | e031-e035 / e036-e040 / e041-e045 / e046-e050
