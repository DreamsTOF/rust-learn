# 练习 08: 注释写法

## 为什么要学这个

在一个看起来"纯 UI"的模板里写注释？听起来有点奇怪——注释不是应该在 Rust 代码里吗？

实际上，**模板内部的注释恰好是区分"初级模板"和"可维护模板"的分水岭。** 当你的 `view!` 超过几十行时，你一定需要这些能力：

1. 解释某个复杂条件渲染的逻辑
2. 标记某个片段将来要重构或扩展
3. 临时代码调试（注释掉某段 UI 输出）

Leptos 的 `view!` 宏支持两种形式的注释——`/* */` 块注释和 `//` 行注释。它们的核心特征只有一句话：**注释只存在于源码中，在渲染结果中彻底消失。**

---

## 问题：我们已经有 Rust 注释了，为什么还需要 view! 内的注释？

### 一个自然的困惑

你可以在组件函数中写 Rust 注释：

```rust
#[component]
fn Exercise() -> impl IntoView {
    // 这是 Rust 行注释
    /* 这也是 Rust 块注释 */
    view! {
        <div>
            <p>"Hello"</p>
        </div>
    }
}
```

这些注释完全有效。但问题在于：**Rust 注释在 view! 宏的外部，无法直接"引用"宏内部的结构。**

想象一下，你想对 `view!` 中某个特定 `<p>` 元素加一条注释，说明它为什么存在：

```rust
view! {
    <div>
        // ✗ 错误：在 view! 宏内部写了 Rust 注释语法
        // Rust 编译器会把 // 当成宏语法的一部分，不是注释
        <p>"关键时刻"</p>
    </div>
}
```

这不会通过编译——`//` 在 `view!` 宏内部不是 Rust 注释，而是宏语法的一部分。

> **根本原因：** `view!` 宏在处理其内部的 tokens 时，使用的是自定义的解析规则。Rust 编译器在宏展开之前，已经把注释从 token 流中剥离了——宏根本"看不到"普通的 Rust 注释。所以 `view!` 必须自己实现注释语法。

### view! 宏如何处理注释

```
你写的代码:
view! {
    /* 这是宏内的注释 */
    <p>"内容"</p>
}

宏接收到的 token 流:
[BlockComment("这是宏内的注释"), OpenTag("p"), Text("内容"), CloseTag("p")]

宏解析:
→ 遇到 BlockComment → 忽略
→ 遇到 OpenTag → 生成 <p> 元素
→ 遇到 Text → 生成文本节点
→ 遇到 CloseTag → 闭合标签

渲染结果: <p>内容</p>  ← 注释消失了
```

## 两种注释语法

### `/* */` 块注释

```rust
view! {
    <div>
        /* 这是一个块注释 */
        <p>"上面的注释不会出现在渲染中"</p>

        /* 块注释
           可以跨多行
           适合写详细的解释 */
        <p>"多行注释也被完全忽略"</p>
    </div>
}
```

块注释从 `/*` 开始，到 `*/` 结束。它可以跨越多行，适合写较长、较正式的解释性文字。

### `//` 行注释（Leptos 0.9 nightly+）

```rust
view! {
    <div>
        // 单行注释，适合简短的标注
        <p>"行注释也不会渲染"</p>

        // 可以连续写多行
        // 每一行都需要以 // 开头
        <p>"这几行注释都是对下面这段 UI 的说明"</p>
    </div>
}
```

行注释从 `//` 开始，到行尾结束。它只能单行使用，适合快速标注。

> **注意：** `//` 行注释在 Leptos 0.9 nightly 中才被支持。如果你使用的是更早版本，只能使用 `/* */` 块注释。不过 nightly 已经是 0.9 的默认通道，大多数情况下 `//` 是可用的。

## 注释 vs HTML 注释

你可能在想：为什么不直接用 HTML 注释 `<!-- -->`？

```html
<!-- 这是 HTML 注释，会出现在 DOM 中 -->
<p>内容</p>
```

对比一下：

| 特性 | `/* */` / `//`（view! 注释） | `<!-- -->`（HTML 注释） |
|------|---------------------------|----------------------|
| 出现在源码中 | ✅ | ✅ |
| 出现在渲染的 DOM 中 | ❌ | ✅（作为 Comment 节点） |
| 用户能看到 | ❌ | ✅（查看页面源代码可见） |
| 增加 DOM 大小 | ❌ | ✅ |
| 适合调试 | ❌（看不见） | ✅（可在 DOM 中直接查看） |
| 适合生产代码 | ✅ | ❌ |

**核心原则：** 面向开发者的注释用 `/* */` 或 `//`，面向调试的临时标记用 `<!-- -->`。

> **一个常见陷阱：** 初学者因为熟悉 HTML，会在 `view!` 中写 `<!-- comment -->`。这在 Leptos 中不是标准支持的语法——`view!` 宏不认识 HTML 注释。如果你确实需要在 DOM 中包含注释节点，可以使用其他显式方式。

## 注释的风格建议

### 什么时候用注释

1. **解释"为什么"而非"是什么"** — 代码已经说明了"是什么"，注释应该说明"为什么存在这个选择"
2. **标记待办事项** — `// TODO: 将来要替换为动态数据`
3. **分离段落** — 用注释行作为视觉分隔符，提高长 `view!` 的可读性

### 什么时候不该用注释

1. **显而易见的内容** — `<p>"用户名"</p>` 不需要注释说"这显示用户名"
2. **替代有意义的变量名** — 应该用变量命名来解释意图，而不是靠注释
3. **注释掉的死代码** — 除非有明确的恢复计划，否则应该删除而不是注释

## 总结

| 概念 | 要点 |
|------|------|
| 为什么需要 | 解释 UI 中的逻辑意图，标注待办，提高模板可读性 |
| `/* */` 块注释 | 可跨行，适合详细说明 |
| `//` 行注释 | 单行，适合简单标注（0.9 nightly+） |
| 是否影响渲染 | 完全不影响——注释在编译时被剥离 |
| vs HTML 注释 | view! 注释不会出现在 DOM 中，HTML 注释会 |
| 核心限制 | 不能使用原生 Rust `//` 语法，必须用宏自己的注释语法 |

**一通百通：** 注释机制虽然在各种语言和模板里形式各异，但本质目标一致——让人理解代码的意图。`view!` 的注释看似是一个小特性，但它反映了一个重要的设计选择：**宏不只是一个"模板引擎"，它是一套独立的微型语言。** 这套语言有自己的语法规则、自己的注释风格、自己的表达式解析逻辑。理解了这一点，你就不会在 `view!` 里用 Rust 注释语法（不会生效），也不会在 `view!` 外用 view! 注释语法（编译错误）。一切回到同一个原则：**你写的是什么层级的代码，就用什么层级的语法。**
