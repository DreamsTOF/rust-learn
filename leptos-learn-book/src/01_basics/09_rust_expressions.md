# 练习 09: Rust 表达式嵌入

## 为什么要学这个

模板是静态的，但 UI 是动态的。一个"动态 UI"的起点，就是在模板中把变量和表达式的结果显示出来。

这个练习要解决的核心问题很简单：**怎么把 Rust 代码的值放进 `view!` 模板里？**

但实际上它涉及一个更深刻的问题：**模板语言和宿主语言之间的边界在哪里？** 有的框架画一条清晰的线（模板里只能访问特定变量），有的框架模糊这条线（模板里可以写任意代码）。Leptos 选择不画线——因为 Rust 的表达式语法本身已经足够安全、可控。

---

## 问题：没有插值，会怎样？

假设你的组件里有一个变量：

```rust
let name = "Leptos";
```

你想让它在页面上显示为 "Hello, Leptos!"。没有表达式插值的话，你只能：

```rust
// 方式一：全部在 view! 外部拼接好
let text = format!("Hello, {name}!");
view! {
    <p>{text}</p>
}

// 方式二：拆成多个文本节点
view! {
    <p>"Hello, " /* 这里没法直接插入 name */ "!"</p>
}
```

方式一的问题是：**格式逻辑被移到了 view! 外部**，模板失去了对"这个文本是怎么构成的"的直接可见性。当 UI 渲染逻辑复杂起来，会变成一大片变量定义 + 一个巨大的 view!——阅读代码时需要不断上下跳跃。

**插值（interpolation）就是解决这个问题的：让你在模板中直接嵌入任意 Rust 表达式，模板即逻辑，逻辑即模板。**

---

## `{ }` — 模式切换器

在 `view!` 宏中，`{ }` 是一个"模式切换器"（mode switch）：

```
view! 的解析模式:
┌─────────────────────────────────────────────┐
│  HTML 模式（默认）                            │
│  • 解析标签、属性、文本                        │
│  • 文本必须用 " " 包裹                        │
│                                              │
│  遇到 { → 切换到 Rust 模式                    │
│  ┌─────────────────────────────────────┐     │
│  │  Rust 模式                            │     │
│  │  • 解析任意 Rust 表达式               │     │
│  │  • 表达式的值必须实现 IntoView        │     │
│  │  • 可以是变量、计算、函数调用          │     │
│  └─────────────────────────────────────┘     │
│  遇到 } → 切换回 HTML 模式                    │
└─────────────────────────────────────────────┘
```

每次进入 `{ }` 都是进入了 Rust 世界。你可以在里面做任何 Rust 表达式能做的事——读取变量、算术运算、方法调用、闭包、match……因为这就是 Rust。

### 基本变量插值

```rust
let name = "Leptos";
let year = 2026;

view! {
    <div>
        <p>"Hello, " {name} "!"</p>
        <p>"今年是 " {year} " 年"</p>
    </div>
}
```

渲染结果：

```
Hello, Leptos!
今年是 2026 年
```

注意这里的结构：`"Hello, " {name} "!"` 实际上生成了**三个并列的文本/表达式节点**——文本 "Hello, "、变量 name 的值、文本 "!"。它们最终在 DOM 中呈现为连续的文本。

### 表达式计算

你不仅可以直接插变量，还可以插入计算：

```rust
let year = 2026;

view! {
    <p>"明年是 " {year + 1} " 年"</p>
}
```

`{year + 1}` 在编译时不是常量折叠（虽然优化器可能会做），但关键在于：**这是合法的 Rust 表达式**。你可以在 `{ }` 里写任何求值表达式，`view!` 宏不会限制你，也不会做任何沙箱处理。

### 使用 format! 宏

当需要组合复杂字符串时，`format!` 是最自然的方式：

```rust
let name = "Leptos";

view! {
    <p>{format!("{name} 版本 0.9 已发布")}</p>
}
```

对比两种写法：

```rust
// 拆开写（可读性较差）
<p>"用户 " {name} " 在 " {year} " 年使用了 " {version} " 版本"</p>

// 用 format!（可读性更好）
<p>{format!("用户 {name} 在 {year} 年使用了 {version} 版本")}</p>
```

> **选择标准：** 如果文本结构是线性的（少数几个变量穿插在固定文本中），拆开写更直观。如果文本结构复杂或涉及条件格式化，`format!` 更合适。

## 表达式的值必须实现 `IntoView`

关键限制：`{ }` 中的表达式结果必须实现 `IntoView` trait。

这决定了什么东西可以直接嵌入：

```rust
// ✅ 可以——String 实现了 IntoView
{ format!("Hello") }

// ✅ 可以——&str 实现了 IntoView
{ "Hello" }

// ✅ 可以——数字类型实现了 IntoView
{ 42 }
{ 3.14 }

// ✅ 可以——HtmlElement 实现了 IntoView
{ view! { <p>"Nested"</p> } }

// ❌ 不可以——Vec<T> 没有实现 IntoView
{ vec!["a", "b"] }

// ❌ 不可以——Option<T> 没有默认实现
{ Some("hello") }
```

> **设计动机：** `IntoView` 确保了嵌入的内容一定能被框架渲染为 DOM。不能渲染的东西（如 Vec 或 Option）会直接编译报错，而不是在运行时静默失败。这是 Rust 哲学中"把错误在编译期暴露"的体现。

## 与其他框架的对比

| 框架 | 插值语法 | 限制 |
|------|---------|------|
| Leptos | `{ expression }` | 结果必须实现 `IntoView` |
| React JSX | `{ expression }` | 必须返回可渲染值 |
| Vue | `{{ expression }}` | 只能访问 data/computed 中定义的属性 |
| Svelte | `{ expression }` | 任意 JS 表达式 |

**关键差异：** 大多数框架的模板插值是在"受限环境"中执行的——Vue 的模板表达式只能访问预定义的属性和全局函数。Leptos 的 `{ }` 没有限制——因为 `view!` 宏展开后在 Rust 的编译单元中，所有 Rust 的访问控制规则（私有/公有、作用域）自然适用。

> **这意味着什么？** 你在 `{ }` 中嵌入 `std::process::Command` 也能通过宏展开——但它（在 WASM 环境下）会在链接时失败，因为 WASM 没有进程。这不是 `view!` 宏的限制，而是目标平台的限制。这种"宏不设防"的做法是把安全性托付给 Rust 编译器而不是模板引擎。

## 深入：IntoView 的桥梁作用

```
你写的           view! 宏展开         运行时
┌────────┐    ┌──────────────┐    ┌──────────┐
│ {name} │ → │ name 变量    │ → │ 文本节点  │
│ &str   │   │ IntoView::() │   │ DOM Text  │
├────────┤    ├──────────────┤    ├──────────┤
│ {42}   │ → │ 42_i32       │ → │ 文本节点  │
│ i32    │   │ IntoView::() │   │ DOM Text  │
├────────┤    ├──────────────┤    ├──────────┤
│ {f(x)} │ → │ f(x) 返回值  │ → │ 视返回值  │
│ ?      │   │ IntoView::() │   │ 类型而定  │
└────────┘    └──────────────┘    └──────────┘
```

`IntoView` 充当了 Rust 值和 DOM 节点之间的桥梁。它允许 `view!` 宏统一处理各种类型的表达式结果——不管是字符串、数字还是嵌套的 `HtmlElement`。

## 总结

| 概念 | 要点 |
|------|------|
| 为什么需要 | 让模板能包含动态数据，避免把逻辑和显示分离 |
| `{ }` 是什么 | view! 中的"模式切换器"——从 HTML 模式进入 Rust 模式 |
| 可以插什么 | 任何实现了 `IntoView` 的 Rust 表达式 |
| 变量插值 | `{name}` 直接嵌入变量值 |
| 表达式计算 | `{year + 1}` 先计算后嵌入 |
| format! | `{format!("...{}...", var)}` 格式化字符串 |
| 核心限制 | 表达式结果必须实现 `IntoView`——编译期检查，零运行时开销 |

**一通百通：** 表达式嵌入看似是"模板语言基本功"，但 Leptos 的做法与其他框架有本质区别——它没有发明一套"模板表达式语言"，而是直接用了 Rust 表达式本身。这意味着没有学习曲线、没有语法子集、没有"在模板里能做什么不能做什么"的心理负担。你会发现，当宿主语言本身就是表达式语言时，模板插值的实现可以优雅到几乎不需要解释——`{ }` 就是"在这里插入一段 Rust 代码"的字面意思。
