# 练习 10: 块级表达式

## 为什么要学这个

在上一节（练习 09）我们学会了用 `{ }` 嵌入变量和简单表达式。但现实世界的 UI 逻辑常常需要更复杂的操作——定义一个临时变量、做一次条件判断、执行一段计算逻辑。

你可能本能地想：**"那我先把逻辑写在 view! 外面，然后把结果存到一个变量里，再在 view! 中使用这个变量。"**

这个思路没错，但有时把逻辑"内联"到 view! 内部会更清晰——特别是当这个变量只在此处使用一次时。Rust 的"块表达式"（block expression）恰好就是为这种场景设计的：**你可以在 `{ }` 内写多条语句，最后一条表达式作为整个块的值。**

---

## 问题：什么时候应该把逻辑放在 view! 内部？

### 一个场景

假设你要在页面上显示一个计算结果：

```rust
let base = 100;
let rate = 0.8;
let result = base * rate as i32;

view! {
    <p>"计算结果: " {result}</p>
}
```

这毫无问题——`result` 在外部计算，在 view! 中引用。

但如果这个 `result` 只在这个 `<p>` 中用一次呢？你仍然需要：

1. 在 view! 上方定义一个变量
2. 阅读代码的人需要在函数开头找到 `result` 的定义
3. 当 view! 中引用了多个这类"一次性变量"时，函数开头会堆满临时变量

**块表达式就是用来解决这个"定义-使用"距离问题的**——它让你在需要值的地方直接定义和计算，不用跑到别处。

### "内联" vs "外提"的权衡

```
外提（传统方式）:

let result = base * rate as i32;  // 定义在函数开头
let other = some_function();       // 另一个临时变量
let now = get_current_time();      // 又一个

view! {
    <p>"计算结果: " {result}</p>
    <p>"其他值: " {other}</p>
    <p>"时间: " {now}</p>
}

阅读流程: 先读变量定义 → 找到 view! → 再回看变量名
          ↑ 需要多次跳转

内联（块表达式）:

view! {
    <p>"计算结果: " { let rate = 0.8; (100.0 * rate) as i32 }</p>
}

阅读流程: 直接在这里看到计算逻辑
          ↑ 无需跳转
```

选择哪个？核心标准是：**这个变量/逻辑是否在多个地方被引用？**

- 只引用一次 → 内联（块表达式）
- 引用多次 → 外提（普通变量）
- 逻辑很复杂（超过 3-5 行） → 外提（甚至提取为单独函数）

## 块表达式基础

### 单个表达式

最简单的块表达式——没有语句，只有一个表达式：

```rust
view! {
    <p>{ 1 + 2 }</p>
}
```

`1 + 2` 本身就是表达式，`{ 1 + 2 }` 在 view! 中被解析为一个 Rust 块，块的值是 `3`。

### 多语句块——最后一条表达式是返回值

```rust
view! {
    <p>
        "计算结果: "
        {
            let x = 1;
            let y = 2;
            x + y          // ← 没有分号！这是块表达式的返回值
        }
    </p>
}
```

这里的关键：`x + y` 没有分号。在 Rust 中，**在块的最后一条表达式上省略分号，这个表达式的值就成为了块的值。**

加上分号会怎样？

```rust
{
    let x = 1;
    let y = 2;
    x + y;    // ← 加了分号，变成语句，块的值变成 ()
}
```

`()` 不实现 `IntoView`，所以编译会报错。

> **记忆口诀：** "分号是语句，没分号是表达式。最后一个没分号的就是返回值。"

### 作用域隔离

块表达式内部定义的变量**只在块内可见**：

```rust
view! {
    <p>
        {
            let secret = "只在块内可见";
            secret
        }
    </p>
}
// 这里不能访问 secret——编译错误！
```

这其实是一个安全特性：**临时变量不会泄漏到外部作用域**，不会污染组件的命名空间。

```
┌────────────────────────────────────────┐
│ 组件函数作用域                          │
│                                        │
│  let name = "visible everywhere";      │
│                                        │
│  view! {                               │
│      <p>                               │
│ ┌─── {                                │
│ │       let tmp = "block-only"; ← 块内  │
│ │       tmp                            │
│ └─── }                                │
│      </p>                              │
│  }                                     │
│                                        │
│  // tmp 在这里不可见                     │
└────────────────────────────────────────┘
```

## 块内 if/else 表达式

Rust 中 `if/else` 是表达式（不是语句），可以在块的末尾作为返回值：

```rust
view! {
    <p>
        "状态: "
        {
            let score = 85;
            if score >= 60 {
                "及格"       // if 分支的值
            } else {
                "不及格"     // else 分支的值
            }
        }
    </p>
}
```

这段代码：

1. 在块内定义 `score = 85`
2. 用 `if/else` 判断分数
3. 整个 `if/else` 表达式的值作为块的值
4. 这个值被渲染到 `<p>` 中

**所有分支的类型必须一致：**

```rust
{
    let cond = true;
    if cond {
        "yes"        // &str
    } else {
        "no"         // &str —— 类型一致，通过
    }
}
```

如果分支类型不一致，Rust 编译器会在编译时报错：

```rust
{
    let cond = true;
    if cond {
        "yes"        // &str
    } else {
        42           // i32 —— 类型不一致！编译错误
    }
}
```

> **这是 Rust 类型系统在帮忙：** 它强迫你在设计条件渲染时确保所有分支返回相同类型。这个看似啰嗦的要求，实际上防止了运行时"期望字符串却得到数字"这类 bug。

## 块表达式 vs 提取函数

复杂的块可能超过 5 行。这时候你需要考虑：是否应该提取成一个单独的函数？

```rust
// 内联（5 行以内）
view! {
    <p>{ let a = 10; let b = 20; let c = a * b; c.to_string() }</p>
}

// 提取成函数（超过 5 行或逻辑复杂时）
fn compute_display() -> String {
    let a = 10;
    let b = 20;
    let c = a * b;
    c.to_string()
}

view! {
    <p>{compute_display()}</p>
}
```

|  | 块表达式 | 提取函数 |
|--|---------|---------|
| 逻辑位置 | 在 view! 内部 | 在函数外部 |
| 可测试性 | 不便于单元测试 | ✅ 可单独测试 |
| 可复用性 | 仅此处使用 | ✅ 可多处调用 |
| 代码行数 | 更紧凑 | 更多样板 |

**基本规则：** 块表达式不超过 3-5 条语句。超过了就提一个函数出来。

## 使用 to_string() 转换类型

注意上面示例中的 `.to_string()`：

```rust
{
    let a = 10;
    let b = 20;
    let c = a * b;        // c: i32
    c.to_string()          // i32 → String
}
```

实际上 `i32` 也实现了 `IntoView`，所以直接返回 `c` 也是可以的：

```rust
// 两种方式都可以
{ let a = 10; let b = 20; a * b }              // ✅ i32 → IntoView
{ let a = 10; let b = 20; (a * b).to_string() } // ✅ String → IntoView
```

> **背后原理：** `IntoView` 为 `i32`、`f64`、`String`、`&str` 等常见类型都有实现。块表达式返回哪种类型取决于你的需要，只要它实现了 `IntoView` 就行。

## 总结

| 概念 | 要点 |
|------|------|
| 什么是块表达式 | `{ 语句; 语句; 最后的值 }` —— 多条语句 + 一个返回值 |
| 返回值规则 | 最后一条不带分号的表达式就是块的值 |
| 作用域 | 块内变量在块外不可见，隔离性好 |
| if/else 在块内 | `if/else` 作为表达式，所有分支类型必须一致 |
| 何时用块表达式 | 一次性的临时计算，逻辑简单（3-5 行以内） |
| 何时不用 | 逻辑复杂、多处引用、需要测试——提取为函数 |

**一通百通：** 块表达式是 Rust 语言"一切皆表达式"哲学在 UI 模板中的自然延伸。JSX 需要 IIFE（立即执行函数表达式）才能在模板中写多条语句——因为 JSX 的 `{ }` 只能包含表达式而非语句。但 Rust 的 `{ }` 天生就是表达式（可以包含语句并产生值），所以 `view!` 不需要任何特殊机制就支持了"模板内多步骤计算"。这不是 Leptos 的功能，而是 Rust 语法的直接受益。**Leptos 不强加自己的模板语言——它只是给 Rust 的表达式能力套上了一层 HTML 的外壳。**
