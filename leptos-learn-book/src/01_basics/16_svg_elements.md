# 练习 16: SVG 元素

## 为什么要学这个

HTML 元素（`div`、`p`、`button`）适合做文档和界面布局。但有些东西用 HTML 做不了——或者说，做起来非常痛苦：

- 画一个圆形的图标
- 画一条连接两个节点的曲线
- 画一个实时更新的仪表盘（速度表、进度环）
- 画一个可缩放的地图

这就是 SVG（Scalable Vector Graphics）的舞台。SVG 是一种在 HTML 中嵌入矢量图形的标准，浏览器原生支持。

在 Leptos 中，SVG 的使用方式极其简单：**`view!` 宏直接支持 SVG 标签**。不需要额外的库，不需要特殊的配置。你唯一需要学的，就是 SVG 本身。

这个练习回答：

1. **为什么 `view!` 直接就能写 SVG？** — 宏的处理机制怎么覆盖到 SVG 的？
2. **`viewBox` 是什么？为什么不用 `width`/`height` 就够了？** — 坐标系统是 SVG 的核心概念
3. **`<circle>`、`<rect>`、`<text>` 这些元素的本质是什么？** — 它们和 `div`、`p` 有什么不同？

---

## 从问题出发

### 一个最简的 SVG

```rust
view! {
    <svg viewBox="0 0 200 100" xmlns="http://www.w3.org/2000/svg">
        <circle cx="50" cy="50" r="30" fill="red"/>
        <rect x="90" y="20" width="80" height="60" fill="blue"/>
        <text x="50" y="90" text-anchor="middle" fill="white" font-size="12">
            "圆形"
        </text>
    </svg>
}
```

这在浏览器中渲染出：

```
         ╭─────────────╮
    ╭────╯             │
    │     ╭───╮        │
    │     │圆│        │
    │     ╰───╯        │
    │   红色圆形        │
    ╰──────────────────╯
                      ╭─────────╮
                      │         │
                      │  矩形   │
                      │         │
                      ╰─────────╯
                      蓝色矩形
```

它看起来跟 `view!` 中的普通 HTML 元素几乎一样。实际上，`view!` 对 SVG 的处理方式也确实跟 HTML 一样——**把标签名映射到对应的 DOM 创建操作**。

### `view!` 为什么能处理 SVG？

`view!` 宏的匹配规则很简单：

```
<tag>  →  在 leptos::html 模块中查找 tag 对应的函数
          如果找到 → 创建 HTML 元素
          如果没找到 → 尝试创建 SVG/自定义元素
```

对于 `<svg>`、`<circle>`、`<rect>`、`<text>` 这些标签，`view!` 会识别出它们属于 SVG 命名空间，并调用对应的 DOM API 创建 SVG 元素。

```
view! 宏的标签解析流程：

      <div>           →  识别为 HTML 元素
      <p>             →  识别为 HTML 元素
      <button>        →  识别为 HTML 元素
      <svg>           →  识别为 SVG 元素（特殊处理）
      <circle>        →  识别为 SVG 元素（在 <svg> 上下文中）
      <rect>          →  识别为 SVG 元素
      <text>          →  识别为 SVG 元素
```

> **一个容易踩的坑：** SVG 元素必须包裹在 `<svg>` 标签中。如果你在 `<svg>` 外面写 `<circle>`，`view!` 会尝试创建 HTML 元素 `<circle>`——它不存在，会默默失败或不渲染。

## `viewBox` —— SVG 的坐标系统

### 像素 vs 逻辑坐标

这是初学者最容易困惑的点。`<svg>` 本身的 `width` 和 `height` 决定了它在页面上的**物理大小**（占多少像素）。但内部元素的坐标（`cx`、`cy`、`x`、`y`）不是直接对应物理像素的，它们对应一个**逻辑坐标系统**——由 `viewBox` 定义。

```rust
<svg width="400" height="200" viewBox="0 0 200 100">
    <!-- 逻辑坐标是 200×100 的虚拟画布 -->
    <!-- 物理大小是 400×200 像素 -->
</svg>
```

```
物理尺寸: 400×200 px
┌──────────────────────────────────────────┐
│                                          │
│  逻辑坐标: 0,0 ────────────────── 200,0  │
│  ┌─────────────────────────────────────┐  │
│  │                                     │  │
│  │  逻辑空间自动缩放                    │  │
│  │  200×100 → 放大到 400×200          │  │
│  │                                     │  │
│  │  0,100 ───────────────── 200,100   │  │
│  └─────────────────────────────────────┘  │
│                                          │
└──────────────────────────────────────────┘
```

`viewBox` 的四个值：

| 参数 | 含义 |
|------|------|
| `min-x` | 逻辑坐标系左上角的 X |
| `min-y` | 逻辑坐标系左上角的 Y |
| `width` | 逻辑坐标系的宽度 |
| `height` | 逻辑坐标系的高度 |

所以 `viewBox="0 0 200 100"` 的意思是："创建一个 200×100 的逻辑画布，从原点 `(0,0)` 开始。"

当逻辑坐标和物理尺寸不同时，SVG 会**自动缩放**逻辑坐标来匹配物理尺寸。这就是为什么"矢量图放大不模糊"——你的逻辑坐标是分辨率无关的。

### 元素的坐标属性

```
viewBox 坐标系 (200×100)
┌──────────────────────────────────┐
│ (0,0)                            │
│                                  │
│        circle(cx=50, cy=50)      │
│            ╭───╮                 │
│            │ 圓 │                │
│            ╰───╯                 │
│                                  │
│                        rect      │
│                   ╭──────────────╮│
│                   │ 矩形         ││
│                   ╰──────────────╯│
│                                  │
│  text(x=50, y=90)                │
│  "圆形"                          │
│                                  │
│                                  │
│ (0,100)                  (200,100)│
└──────────────────────────────────┘
Y 轴向下递增（与数学坐标系相反）
```

关键规则：

- **X 向右递增，Y 向下递增**（跟屏幕坐标一致，跟数学坐标的 Y 轴方向相反）
- **`cx`/`cy` 是圆心**，不是左上角
- **`x`/`y` 在 `rect` 中是左上角**，在 `text` 中是基线的起始位置
- 坐标值都是逻辑坐标单位，不是物理像素

## 基本 SVG 元素

### `<circle>` — 圆形

```rust
<circle cx="50" cy="50" r="30" fill="red"/>
```

| 属性 | 含义 | 说明 |
|------|------|------|
| `cx` | center-x | 圆心 X 坐标 |
| `cy` | center-y | 圆心 Y 坐标 |
| `r` | radius | 半径 |
| `fill` | 填充颜色 | 颜色名、hex、rgb 均可 |

### `<rect>` — 矩形

```rust
<rect x="90" y="20" width="80" height="60" fill="blue"/>
```

| 属性 | 含义 | 说明 |
|------|------|------|
| `x` | 左上角 X | |
| `y` | 左上角 Y | |
| `width` | 宽度 | |
| `height` | 高度 | |
| `fill` | 填充颜色 | |
| `rx` / `ry` | 圆角半径 | 可选，默认是直角 |

### `<text>` — 文本

```rust
<text x="50" y="90" text-anchor="middle" fill="white" font-size="12">
    "圆形"
</text>
```

`<text>` 和 HTML 的 `<p>` 最大的不同是：**SVG 文本没有自动换行**。你需要手动控制文本位置。

| 属性 | 含义 | 说明 |
|------|------|------|
| `x` | 文本位置 X | 取决于 `text-anchor` |
| `y` | 文本基线 Y | Y 不是上边缘，是基线位置 |
| `text-anchor` | 水平对齐 | `start`/`middle`/`end` |
| `dominant-baseline` | 垂直对齐 | `hanging`/`middle`/`baseline` |
| `fill` | 文字颜色 | |
| `font-size` | 字号 | |

> **`text-anchor="middle"` 的妙用：** 当文本需要居中对齐时（比如在圆形中央），设置 `text-anchor="middle"` 并让 `x` 等于圆心的 `cx`。这样，无论文本多长，它都会自动居中。

## SVG vs HTML 元素的关键差异

| 维度 | HTML 元素 | SVG 元素 |
|------|----------|---------|
| 定位模型 | 文档流（块/行内/弹性/网格） | 绝对坐标（x, y） |
| 缩放行为 | 像素固定 | 矢量缩放（viewBox 控制） |
| 尺寸单位 | px, em, rem, % | 逻辑坐标单位 |
| 样式继承 | 继承父元素 CSS | 不继承父元素 CSS（各元素独立设置） |
| 事件 | 全支持（click, hover...） | 全支持 |
| 动画 | CSS animation / transition | CSS + SMIL（SVG 原生动画） |

**最常见的误解：** 很多人以为 SVG 是"图片格式"，不能交互。实际上 SVG 元素跟 HTML 元素一样可以绑定事件、可以动画、可以响应式更新：

```rust
view! {
    <svg viewBox="0 0 200 100">
        <circle
            cx="50" cy="50" r="30"
            fill="red"
            on:click=move |_| tracing::info!("圆形被点击")
        />
    </svg>
}
```

SVG 不是图片，它是**可编程的矢量图形**。

## 在 view! 中使用 SVG 的注意事项

### 1. 必须设置 `xmlns`

虽然现代浏览器会自动推断 `xmlns="http://www.w3.org/2000/svg"`，但为了规范性和跨浏览器兼容，建议始终加上。

### 2. 文本必须用双引号

跟 `view!` 中的 HTML 文本一样，SVG `<text>` 内的文本也需要双引号：

```rust
<text x="50" y="50">"Hello"</text>   // ✅
<text x="50" y="50">Hello</text>     // ❌ 会被解析为变量名
```

### 3. 属性名使用 kebab-case

SVG 属性（如 `text-anchor`、`font-size`、`stroke-width`）在 `view!` 中直接写 kebab-case 即可，不需要转成 camelCase：

```rust
<text text-anchor="middle" font-size="12" .../>   // ✅ 直接写，跟 HTML 一样
```

**这和 React 不同：** React 的 JSX 中 SVG 属性需要用 camelCase（`textAnchor`、`fontSize`）。Leptos 的 `view!` 则跟 HTML 保持一致——保留原始属性名，不做转换。

## 一通百通

```
SVG in Leptos = view! + SVG 标准

你学会的其实是：
  view! 不是"HTML 专用"的——它是"浏览器 DOM"的统一接口
  ↓
  HTML 元素和 SVG 元素共享同一套 view! 语法
  ↓
  你可以把 SVG 当作"另一种 HTML 标签"来理解和使用
```

| 知识点 | 核心理解 |
|--------|---------|
| `<svg viewBox="0 0 200 100">` | 定义逻辑坐标系统，自动缩放 |
| `<circle cx cy r fill>` | 圆心坐标、半径、填充色 |
| `<rect x y width height fill>` | 左上角坐标、宽高、填充色 |
| `<text x y text-anchor fill font-size>` | 文本位置和对齐方式 |
| SVG 元素可交互 | 支持 `on:click` 等所有 Leptos 事件 |
